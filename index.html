    What does DIVE-Bench measure?

    Educational video QA

    634 QA items from 317 educational source videos. Questions target visible text and subtitles across long videos. Evaluation uses video frames, not an audio-input protocol.

    Ranked by Open MOS, a 0–5 answer-matching score from a Qwen3-VL-32B text judge.

    Fine-grained motion

    Predict a hand trajectory on a 3×3 grid. The v2 preview uses the first 1,000 of 3,243 source records, with invalid reference positions masked.

    Ranked by Grid Accuracy; error, transitions and Token F1 provide complementary measures.

    GRT: reuse stable visual computation

    Gated Residual Tokenization reuses cached patch projections where the image stays stable and recomputes changed regions.

    1. Encode the reference

      Compute and cache the full patch grid.

    2. Update changed patches

      Reuse stable projections; recompute residual change.

    3. Keep the full grid

      Pass the full token sequence to the vision-language model.

    Current released profiles use eight sampled frames and keep the token count unchanged. Scene merging is an optional method component, disabled in these profiles. Patch reuse does not measure end-to-end FLOPs or establish high-FPS performance.

    Reproduce the results

    Rebuild the published tables from the numerical evidence, or follow the linked protocols for model inference.

    Commands and reproduction requirements

    Reaggregating saved evidence does not rerun models. Fresh inference requires GPU resources and authorized source data; private source videos, HDF5 files and derived annotations are not bundled or licensed for redistribution by this code release.

    setup.sh

    git clone --branch main --single-branch \
  https://github.com/Hai-chao-Zhang/DenseVideoUnderstand.git DIVE-Bench
cd DIVE-Bench
python -m pip install 'PyYAML>=6'
# 29 Educational + 19 High-Motion preview + 12 comparison rows (60 CSV records).
# Pinned v2 manifest: 1f64ff54ec8eb09d72c37d6ef3a944e8ccae0a58fe5b4d45fabdfb0a7449d0dc
python -m tools.densevideo.build_complete_leaderboard --verify-only
python -m tools.densevideo.build_complete_leaderboard --output outputs/leaderboard-complete
# Open outputs/leaderboard-complete/leaderboard.html; output must be new.

    Protocol notes

    1. 01 Use a dedicated environment; minimal DIVE-Bench and upstream lmms-eval share a Python namespace.
    2. 02 Keep the 1,000-item preview separate from the full 3,243-item task and from different API protocols.
    3. 03 Record model/data revisions, frame budgets, predictions, quality gates and request telemetry.

    Framework submissions
    VLMEvalKit #1686 is open for review; lmms-eval #1521 is a draft. Neither has been merged (checked 26 October 2026). Data permissions and manuscript/protocol differences remain documented in the public audit.
